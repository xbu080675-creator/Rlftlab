# RiftLab dev.59 ～ dev.78 开发路线

> 基线：`main` / `1.0.0-dev.58`
>
> 原则：GitHub 是唯一主仓库、版本真源、构建源和正式 Release 源；Gitee 只作为中国大陆源码镜像，不反向决定版本历史，也不承担 APK 主分发。
>
> 当前主线：先把赛事内容与数据完整度补齐，再把已有的赛程、战队、实时状态、赛后、Timeline、赛事规则/抽签/研究档案能力汇入“沙盘”。

---

## 0. dev.58 基线审计

当前仓库已经不再是早期 30 个版本时的 MVP。代码基线实际已经到 `dev.58`，目前已经具备：

- PRE / LIVE / POST 三段式赛事生命周期；
- Riot Schedule / Standings / Live Stats 与多级降级链；
- LPL 与全球赛事目录、赛区订阅、国际赛事入口；
- Team Archive、人物库、运营关系、电竞图谱；
- 比赛 Timeline、本地事件溯源、历史小局归档；
- Bilibili / Riot / YouTube 回放链路与 App 内播放；
- OP.GG 历史补全与全球赛后数据补充；
- Cito 作为可选全链路 Provider；
- 赛事规则、签位/抽签治理、年度 Tournament Research；
- RiftScreen 悬浮副屏；
- dev.58 的中国大陆优先 OTA + GitHub 兜底框架。

当前仍有几条明显缺口：

1. `DEV_CHANGELOG.txt` 的可见记录落后于实际 `dev.58`，需要把版本史重新对齐；
2. dev.58 的大陆 OTA 方案依赖额外镜像分发，dev.59 改为 GitHub 唯一 Release + APP 内请求级 GitHub 更新加速，避免跨境大文件二次上传和镜像附件体积限制；
3. 赛事研究层已经有“版本 / 规则 / 抽签 / 赛程 / 排名”槽位，但大量赛事仍停留在 provider/待同步状态，内容覆盖率还不够；
4. 赛前阵容、Rank、状态、转会，赛中事件，赛后完整选手/英雄/装备/资源数据仍需要继续补齐；
5. 目前没有独立 Sandbox / 沙盘模块，沙盘应建立在真实赛事模型上，而不是另做一套 Mock 游戏。

# 第一阶段：赛事数据补全与国内分发稳定化

## dev.59 — GitHub 唯一 Release + APP 内更新加速

目标：长期保留 GitHub 作为唯一 APK 正式发布源，同时解决中国大陆检查更新与下载链路不稳定的问题。

- GitHub Actions 构建 APK 与 `latest.json`，只发布到 GitHub 固定 `dev-latest` Release；
- 发布顺序保持“APK 先上传，latest.json 最后切换”，再清理旧 APK；
- 客户端检查更新先直连 GitHub，失败或超时才临时启用 GitHub 更新加速；
- 更新加速只允许访问 RiftLab 官方 GitHub `dev-latest` manifest / APK 白名单，不支持任意 URL；
- 不创建 `VpnService`，不修改系统代理，不接管其他 APP、赛事数据、直播、回放或普通 API 流量；
- 加速请求结束后立即断开，不保持系统级网络状态；
- APK 下载支持 HTTP Range 断点续传，直连中断后可从加速通道继续；
- manifest / APK 保留 HTTPS、SHA-256、package、versionCode、固定 DEV 签名证书校验；
- Gitee 继续作为源码镜像，不承担 APK 主分发；S3 对象存储不再是 dev.59 必需依赖。

验收：GitHub 可直连时完全不经过加速节点；GitHub 直连不稳定时，仅更新请求临时走加速通道；下载中断后可续传；加速层无法把非 RiftLab GitHub Release URL 注入更新流程；构建发布链不再等待 Gitee 大文件上传。

## dev.60 — 版本史与数据源治理清账

目标：把快速迭代留下的历史不一致全部收口。

- 补齐 dev.35～dev.58 的正式开发履历；
- `DEV_CHANGELOG.txt`、`build.gradle.kts`、Release 文案统一；
- 清理一次性 apply/fix workflow，保留真正需要长期运行的工作流；
- 给 Riot / Mirror / OP.GG / Cito / Official / Cache 建统一 provenance 标签；
- 明确“官方确认 / Provider 返回 / 结构推导 / 本地缓存 / 待核实”五级展示。

## dev.61 — 全球赛事目录完整化

目标：把“能发现赛事”升级为“稳定、可浏览、可归档的赛事目录”。

- 为 LPL、LCK、LCP、LEC、LTA 及主要次级赛事建立稳定目录身份；
- 国际赛事统一 family：First Stand / MSI / Worlds / EWC / Americas Cup / EMEA Masters / Demacia 国际项目 / WSCL；
- 赛事按“年份 → 赛段/届次 → 阶段”组织；
- 解决同名赛事、改名赛事、次级联赛与主联赛混淆；
- 目录不因当前是否有 LIVE 比赛而改变层级。

## dev.62 — Tournament Edition 年度赛事档案

目标：每一届赛事成为可长期引用的独立实体，而不是一组临时赛程。

每届赛事固定保存：

- 年份与正式名称；
- 比赛版本 / Patch；
- 参赛队与资格来源；
- 规则与赛制；
- 抽签 / 签位 / 分组；
- 赛程；
- 排名 / 淘汰树；
- 最终名次与冠军；
- MVP / FMVP / POG 等已核实奖项；
- 数据来源与更新时间。

旧届次不得被新一届数据覆盖。

## dev.63 — 资格、积分与晋级路径中心

目标：把“排名”和“怎么进下一阶段”连接起来。

- Championship Points 独立于联赛排名；
- 世界赛 / MSI / First Stand 等赛事资格路径可视化；
- 区域资格赛、冒泡赛、骑士之路等作为明确阶段节点；
- 已锁定、仍可争夺、已淘汰三种状态；
- 任何推演结果必须与官方确认结果区分显示。

## dev.64 — 赛前信息补全

目标：真正补齐 PRE。

- 首发 / 替补 / 教练组；
- 最近正式比赛阵容；
- Rank 与近期英雄池（数据源可用时）；
- 最近 5～10 场状态；
- 转会、首发变动、伤病/缺席等只收录公开确认信息；
- 对局历史、近期交手、红蓝方记录；
- 开赛前“已开播但尚未进入小局”的节目阶段信息继续保持独立。

## dev.65 — 赛中事件标准化

目标：让所有实时源最终输出同一种事件模型。

统一事件：

- 击杀 / 多杀 / 团战窗口；
- 防御塔；
- 小龙 / 龙魂 / 远古龙；
- 峡谷先锋 / 厄塔汗等版本资源；
- 男爵；
- 经济领先变化；
- 关键装备节点；
- 等级 / CS / KDA 变化。

无法确定具体击杀者、受害者或事件顺序时不猜。

## dev.66 — 赛后完整 Game / Series 数据

目标：POST 不再只是一张终局比分卡。

每个小局补齐：

- 双方阵容、英雄、召唤师技能；
- K/D/A、CS、经济、伤害等可用统计；
- 装备终局；
- 龙、塔、男爵等资源；
- BP；
- MVP / POG；
- Series 小局总比分与每局入口；
- Timeline 与回放入口。

## dev.67 — 回放与 Timeline 时间对齐

目标：把“看录像”和“看数据时间轴”变成一个系统。

- Timeline 秒数与 VOD 播放位置建立 offset；
- 点击击杀/龙/团战事件可跳到录像附近；
- 从录像进度反向定位 Timeline；
- 不同平台存在片头、暂停、广告时允许人工校准偏移；
- 校准值仅属于该 VOD，不污染比赛事实数据。

## dev.68 — 赛事内容完整度面板

目标：让 RiftLab 自己知道“缺什么”。

每届赛事显示覆盖率：

- Schedule
- Standings
- Rosters
- Rules
- Draw
- Patch
- Match Stats
- Awards
- Replay
- Timeline

缺失项可以继续由同步器补齐；用户界面明确显示“待同步”，不拿占位数据伪装完整。

# 第二阶段：RiftLab Sandbox / 赛事沙盘

沙盘不是随机生成比赛结果，而是一个“以真实赛事数据为初始条件，可手工改变条件并比较分支”的分析工具。

## dev.69 — Sandbox Core / 沙盘核心模型

目标：建立独立但可复用真实数据的沙盘 Session。

核心对象：

- SandboxSession
- SandboxTeam
- SandboxPlayer
- SandboxDraft
- SandboxMapState
- SandboxObjectiveState
- SandboxTimeline
- SandboxBranch

支持从空白创建，也支持“从真实比赛某个时间点复制到沙盘”。

## dev.70 — 召唤师峡谷战术地图

目标：第一版可交互地图。

- 红蓝双方五个位置节点；
- 三路、河道、野区与主要资源点；
- 拖动选手位置；
- 标记推进、回城、包夹、绕后、视野区域；
- 时间轴拖动；
- 地图状态与比赛数据状态分离。

第一版不追求游戏客户端级像素坐标，先做电竞分析所需的区域级位置模型。

## dev.71 — BP / Draft 沙盘

目标：把 ChampionCatalog 与真实赛事 BP 数据接入沙盘。

- 蓝红方 Ban/Pick；
- BO3 / BO5 小局 BP 记录；
- 选手英雄池提示；
- 已使用英雄 / 全局 BP 规则可配置；
- 从真实比赛一键载入原 BP，再修改一个选择建立分支。

## dev.72 — 阵容与对位沙盘

目标：模拟“换人 / 换线 / 英雄换位 / 首发变更”的结构影响。

- 真实 roster 载入；
- 首发/替补切换；
- TOP/JUG/MID/BOT/SUP 位置调整；
- 对位关系；
- 阵容控制、开团、前排、持续输出、Poke、边线等标签；
- 标签必须说明来自统计、人工规则还是用户手动设置。

## dev.73 — 资源与兵线状态沙盘

目标：让地图不只是五个点。

- 三路兵线状态：推进 / 回推 / 冻结 / 中线；
- 塔状态；
- 小龙层数与龙魂；
- 男爵 / 远古龙；
- 先锋及当版本主要地图资源；
- 双方经济与经济差；
- 重要召唤师技能 / 大招状态以可选标签表达。

## dev.74 — Timeline 分支 / “如果当时不这么打”

目标：沙盘真正进入复盘用途。

- 从真实 Timeline 任意节点创建 Branch；
- 修改一个条件，例如“不接龙团”“上单继续带线”“辅助提前游走”；
- 原始事实线永久只读；
- 沙盘分支用不同颜色/标签明确区分；
- 支持多分支 A/B/C 比较。

## dev.75 — 路线与决策标注

目标：支持教练式复盘语言。

- 打野动线；
- 辅助游走路线；
- TP / 回城窗口；
- 资源交换；
- 交叉地图；
- 视野进入路径；
- 团战进场角度。

重点是可表达“为什么这么走”，而不是假装还原游戏内部不可见信息。

## dev.76 — 沙盘评估引擎 v1

目标：提供解释型评估，不制造虚假的精确胜率。

输出维度：

- 经济与资源风险；
- 人数差；
- 兵线代价；
- 地图资源收益；
- 阵容时间曲线；
- 开团/反开结构；
- Carry 暴露风险；
- 下一资源刷新前的准备时间。

第一版只输出“倾向 / 风险 / 代价 / 可行条件”，不输出没有训练依据的伪精确 `63.7%` 胜率。

## dev.77 — Sandbox Compare / 分支对照复盘

目标：把多个方案真正放在一起比较。

例如同一节点：

- A：接小龙团；
- B：放龙换上塔；
- C：中野入侵上半区。

统一比较：经济、塔、资源、兵线、人员位置、下一步窗口与主要风险。

支持从 Match Detail / Timeline 直接进入 Compare。

## dev.78 — 沙盘 MVP 收口与本地档案

目标：完成第一阶段可长期使用的 Sandbox。

- 沙盘保存 / 重命名 / 删除；
- 从真实比赛创建；
- 空白创建；
- Timeline 分支；
- Draft + 地图 + 资源 + 路线标注；
- 分支对照；
- 导出结构化 JSON；
- 所有推演内容明确标记 `SANDBOX`，永远不能回写覆盖真实比赛档案；
- 为后续 AI 复盘、教练协作、战队训练模板预留接口。

# 3. 这 20 个版本的节奏

- `dev.59～dev.60`：发布链与版本史清账；
- `dev.61～dev.68`：赛事内容完整度冲刺；
- `dev.69～dev.73`：沙盘基础与地图/BP/资源；
- `dev.74～dev.78`：真实比赛分支复盘、评估与 MVP 收口。

完成 dev.78 后，RiftLab 的产品形态应从“赛事数据中心 + 副屏”升级为：

**赛事资料库 + 实时观赛数据层 + 赛后回放/时间轴 + 可分支的电竞分析沙盘。**

这会成为后续 AI 复盘、教练式战术分析、多人协作与更多游戏项目扩展的稳定底座。
