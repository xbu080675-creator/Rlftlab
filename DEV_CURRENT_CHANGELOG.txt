dev.61：修复 GitHub 更新加速在 70MB 级 Release APK 上“显示已启用但长期 0 B”的问题。根据近期针对真实 GitHub Release asset 的公开 Range 测试，原默认 `gh-proxy.com` 在同类大文件请求中出现超时，而 `ghfast.top` 与 `ghproxy.net` 能返回 HTTP 206；因此 dev.61 默认改为 GHFast 主节点 + GHProxy.net 备用节点。客户端现在会在 GitHub 直连、GHFast、GHProxy.net 之间自动回退，并保留同一 `.part` 文件做 HTTP Range 断点续传；加速节点 20 秒无数据即切下一条链路，避免长期停在 0%。更新中心会显示当前实际使用的节点。加速仍只作用于 RiftLab 官方 GitHub `dev-latest` manifest/APK，不创建 VPNService、不修改系统代理、不接管其他流量；下载完成后继续强制校验 SHA-256、包名、versionCode 与固定 DEV 签名证书。版本升级至 1.0.0-dev.61 / versionCode 61。
